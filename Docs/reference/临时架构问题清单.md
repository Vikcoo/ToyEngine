# 临时架构问题清单

本文只记录当前尚未完成、后续高概率需要处理的结构性问题。已解决问题不再保留完整过程，只在文末链接到对应复盘或踩坑记录。

排序综合考虑当前风险和返工成本，不代表必须立即实现。没有真实需求或数据支撑的扩展继续遵循 YAGNI。

## 1. Vulkan 通用资源生命周期与分配策略尚未完成

现象与风险：
- 阶段 B 验证资源常驻到 `SceneRenderer` 销毁，并在销毁前 `WaitIdle()`。
- 动态创建或替换 descriptor、buffer、image 时，直接析构可能早于 GPU 完成使用。
- 当前每个资源独立 `vkAllocateMemory`，启动期上传逐次等待，不适合大量资产或运行时流送。

当前判断：
- 现有方案足够支撑静态网格验证路径，不需要为尚未出现的负载提前实现完整显存系统。
- 扩大 Vulkan 场景范围前，必须先建立按 frame fence 延迟回收；批量上传和显存子分配按实际性能数据引入。

优先检查：
- `Source/Runtime/RHIVulkan/Private/VulkanDevice.cpp`
- `Source/Runtime/RHIVulkan/Private/VulkanBuffer.cpp`
- `Source/Runtime/RHIVulkan/Private/VulkanTexture.cpp`
- [Vulkan 基础资源与 Descriptor 垂直切片](../knowledge/Vulkan基础资源与Descriptor垂直切片.md)

## 2. Shader 与 C++ 资源布局仍是两份手写真相源

现象与风险：
- Shader 使用 group/set 与 binding 宏，C++ 另行维护 `RendererBindGroups`、`RendererBindings` 和 `RHIBindGroupLayoutDesc`。
- Vulkan 已能消费这套约定，但 Validation Layer 不能发现 Shader 与 C++ layout 的语义漂移。

处理方向：
- 下一步只做最小离线反射校验，不直接引入生成代码或完整资产管线。
- 校验不足以覆盖真实新增 Shader 时，再推进 binding 常量和 layout 描述生成。

优先检查：
- `Content/Shaders/Common/RHIDescriptorBindings.glsl`
- `Source/Runtime/Renderer/Private/RendererBindingSlots.h`
- [Shader 资源绑定清单](./Shader资源绑定清单.md)
- [Shader 反射与资源绑定描述推进规划](../architecture/Shader反射与资源绑定描述推进规划.md)

## 3. PBR 与 IBL 仍是质量验证版本

现象与风险：
- specular IBL 使用环境 cubemap mip 链近似，不是正式 GGX 重要性采样预滤波。
- IBL 由 CPU 在运行时预计算，尚无缓存、环境资源选择或热重载。
- 缺少正式曝光、Tonemapping 和 PBR/IBL DebugView，材质输入错误仍较难定位。

处理方向：
- 先补 DebugView，再升级 specular prefilter；缓存和热重载等出现多环境资源需求后再做。
- 保留现有 Environment BindGroup 形状，避免质量升级扩散到高层资源接口。

优先检查：
- `Source/Runtime/Renderer/Private/RenderResourceManager.cpp`
- `Source/Runtime/Renderer/Private/ForwardRenderPath.cpp`
- `Source/Runtime/Renderer/Private/DeferredRenderPath.cpp`
- [PBR 渲染前置规划](../architecture/PBR渲染前置规划.md)

## 4. World 与 Renderer 的 PUBLIC 依赖传播偏粗

现象与风险：
- `Renderer` 当前把 `Core`、`RHI`、`World`、`RenderCore`、`Asset` 全部作为 `PUBLIC` 依赖。
- 下游容易获得不需要的头文件和链接依赖，公共接口变化会扩大重编译范围。

处理方向：
- 先检查 `Renderer/Public` 的真实类型需求，再把仅实现文件使用的依赖改为 `PRIVATE`。
- 不为缩依赖引入新接口层；前向声明和现有模块边界足够时直接使用。

优先检查：
- `Source/Runtime/Renderer/CMakeLists.txt`
- `Source/Runtime/Renderer/Public`

## 5. 游戏侧到渲染侧仍是同步直调

现象与风险：
- `IRenderScene` 当前由 `World::SyncToScene()` 在同一线程直接调用。
- `FRenderResourceManager` 虽已从 `FScene` 拆出，但仍位于同一模块；资源准备、场景注册和 GPU 生命周期尚未形成可跨线程的稳定边界。

当前判断：
- 单线程阶段下同步直调最简单且正确，不需要提前实现渲染线程。
- 真正引入独立 GameThread/RenderThread 前，再以稳定 Component ID 建立命令队列和资源延迟回收契约。

优先检查：
- `Source/Runtime/World/Private/World.cpp`
- `Source/Runtime/Renderer/Private/RendererScene.cpp`
- `Source/Runtime/Renderer/Private/RenderResourceManager.cpp`
- [渲染资源准备阶段解耦复盘](../architecture/架构优化复盘-渲染资源准备阶段解耦第一阶段.md)

## 6. Deferred 的 WorldPosition RT 仍作为调试资源常驻

现象与风险：
- 正式 Deferred 光照已经使用 `Depth + inverse view-projection` 重建世界坐标。
- WorldPosition RT 只服务 `F6/F8` 对照视图，但仍占用 GBuffer 写带宽与显存。
- 当前误差视图混合了插值、RT 存储和重建误差，不能单独衡量深度量化。

处理方向：
- 先增加纯深度误差验证，确认对照价值；不再需要长期校准时移除 WorldPosition RT。
- 新增 Shadow、SSAO、SSR 或 Hi-Z 时继续沿用统一 Reversed-Z 契约。

优先检查：
- `Source/Runtime/Renderer/Private/DeferredRenderPath.cpp`
- `Source/Runtime/Renderer/Private/RendererDepthConvention.h`
- [Reversed-Z 深度约定复盘](../architecture/架构优化复盘-Reversed-Z深度约定.md)

## 当前建议顺序

1. 扩大 Vulkan 动态资源范围前，补通用资源 fence retirement。
2. 为新增 Shader 建立最小 layout 反射校验。
3. 提升 PBR 质量前先补 DebugView，再做正式 specular prefilter。
4. 收窄 `Renderer` 的 PUBLIC 依赖。
5. 只有确定引入独立渲染线程时，才实现 GT/RT 命令队列。
