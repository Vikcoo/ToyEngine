# 单帧执行流

本文档描述 `Engine::Tick` 当前真正实现的执行顺序。当前仍是单线程执行，但 `Engine` 内部已经按接近 UE5 职责边界的帧阶段拆分，便于后续演进到更明确的 GameThread / RenderThread 边界。

## 启动阶段

`Engine::Init()` 当前大体执行以下步骤：
1. 初始化日志系统
2. 初始化内存系统
3. 创建窗口
4. 使用原生窗口句柄和平台呈现回调初始化 RHI 设备；帧命令缓冲由 Device 按帧提供
5. 创建 `FScene`、`SceneRenderer`、`World`
6. 将 `World` 绑定到 Engine 持有的 `FRenderSceneCommandRecorder`；游戏侧不再直接持有 `FScene`
7. 初始化输入系统
8. `bSupportsFullSceneRendering` 后端调用应用层 `SceneSetupCallback`（由 Sandbox 负责场景搭建）；阶段 B Vulkan 延后应用场景搭建，由 Renderer 使用内部验证路径

## 主循环

`Engine::Run()` 会持续执行以下逻辑：
- 计算 `deltaTime`
- 对 `deltaTime` 做上限裁剪
- 检查窗口是否请求关闭
- 调用 `Tick(deltaTime)`

直到请求退出为止。

## 当前每帧顺序

`Engine::Tick()` 当前按以下阶段执行：
1. `PumpPlatformMessages()`：轮询窗口事件。
2. `TickInput(deltaTime)`：推进 `InputManager` 的当前帧输入状态。
3. `TickGameThread(deltaTime)`：完整场景后端先调用应用层 `FrameUpdateCallback`，再调用 `World` 与其 Actor / Component 的 `Tick`；阶段 B Vulkan 没有应用场景对象，只推进空 World。
4. `SendAllEndOfFrameUpdates()`：让 `World` 把脏组件状态记录到 Recorder，随后取走全部命令，并连同相机视图、Framebuffer 尺寸、VSync、渲染路径和调试视图构造 `FRenderFramePacket`。
5. `TickRenderThread(deltaTime, renderFrame)`：先通过 `FScene::ApplyCommands()` 消费场景命令和视图快照，再调用 `RHIDevice::BeginFrame()` 获取 `RHIFrameContext` 并调度当前 `IRenderPath`；阶段 B Vulkan 仍使用内部静态网格验证路径。framebuffer 为零或后端暂不可呈现时返回 `Skipped`，Engine 睡眠 16 ms 避免最小化空转。
6. `EndFrame(deltaTime)`：结束输入过渡态，更新 FPS、当前渲染相机世界坐标与绘制统计；不再直接交换窗口缓冲。

这些函数名借鉴 UE5 的职责划分，但当前只是单线程阶段边界：帧包已切断游戏侧对 `FScene` 的直接调用，`TickGameThread` 和 `TickRenderThread` 仍运行在同一线程，二者之间也还没有线程安全队列。

当前帧命令录制边界由 Device 统一持有。Forward / Deferred RenderPath 只向 `RHIFrameContext::commandBuffer` 写入 Pass 和 Draw，不自行调用 CommandBuffer 的 `Begin/End`。OpenGL Device 在 `EndFrame()` 内通过创建时注入的平台回调执行 `SwapBuffers()`；Vulkan Device 已在同一边界实现 Acquire、Queue Submit 和 Present。

Vulkan 使用两个不同索引：`frameIndex` 选择 CPU 可复用的 frame slot 与 transient Uniform 段，`swapChainImageIndex` 选择本次 Acquire 的颜色图像、深度图像与 present semaphore。CommandPool、CommandBuffer、image-available semaphore 和 submit fence 按 frame slot 管理；render-finished semaphore 与 `D32_Float` depth texture 按交换链图像管理。`m_ImagesInFlight` 还会把交换链图像映射到最近一次提交 fence，避免同一图像仍被 GPU 使用时重新录制。

窗口 resize、VSync 变化以及 `VK_ERROR_OUT_OF_DATE_KHR/VK_SUBOPTIMAL_KHR` 会把 Swapchain 标为待重建。重建前等待 Device idle；最小化期间 surface extent 可能在尺寸检查之后异步变为零，因此创建函数还会二次检查最终 `VkExtent2D` 并返回 `Skipped`。恢复后下一帧重新创建 Swapchain 和每图像同步对象。

FPS 统计每 `0.5` 秒输出一次滑动窗口均值。日志中的 `CameraWS` 直接读取 `FScene::GetViewInfo().CameraPosition`，因此对应刚刚提交渲染的视图，而不是在帧尾重新从相机组件计算；坐标按 `(X, Y, Z)` 输出并保留三位小数。若当前没有有效渲染视图，则回退为零向量。

## 当前 Sandbox 场景内容

`Source/Sandbox/Main.cpp` 当前会在 `SceneSetupCallback` 中创建：
- 一个主模型 Actor（优先导入模型，否则回退到内置立方体）
- 一个位于上方、缩放为 0.5 的第二模型 Actor
- 一个位于点光源位置、缩放为 1/3，并与点光源一起绕原点在 `XZ` 平面公转的模型 Actor
- 一个带 `CameraComponent` 的相机 Actor
- 一个挂在相机 Actor 上的 `FlyCameraController`
- 一个方向光 Actor
- 一个与模型标记共用圆轨道的点光 Actor
- `F1` 切换到 Forward
- `F2` 切换到 Deferred
- `F3` 切换到 Lit 调试视图
- `F4` 切换到 Deferred 并显示 Albedo 调试视图
- `F5` 切换到 Deferred 并显示 Normal 调试视图
- `F6` 切换到 Deferred 并显示 WorldPosition 调试视图
- `F7` 切换到 Deferred 并显示 Depth 调试视图
- `F8` 切换到 Deferred 并显示 WorldPosition 重建误差热力图
- 窗口标题实时显示当前渲染路径和调试视图模式

`FrameUpdateCallback` 运行在 `TickGameThread` 阶段、`World::Tick` 之前。它会处理 `F1` 到 `F8` 的渲染路径 / 调试视图切换，对 `MeshActor` 施加旋转，并驱动点光源及其模型标记绕原点在 `XZ` 平面公转；更新后分别标记 `PrimitiveComponent` / `LightComponent` 脏状态。

## 这一层设计为什么重要

当前项目最关键的边界在于：
- 游戏侧更新发生在 `World` 及其组件体系中
- `Actor` 拥有 Component，`World` 管理 Component 的注册状态；二者不是同一种关系
- 只有 `World` 向 `FRenderSceneCommandRecorder` 写入稳定 ID、状态快照和 SceneProxy 所有权，Component 不保存 Recorder 指针
- 渲染阶段只从 `FRenderFramePacket` 读取，并由 `FScene` 消费命令

`SendAllEndOfFrameUpdates()` 现在是显式的游戏侧提交边界。后续引入独立渲染线程时，只需把 `FRenderFramePacket` 的直接参数传递替换为有界线程安全队列，并补齐阻塞、丢帧、关闭与资源延迟回收策略。

组件销毁不依赖 C++ 析构函数临时寻找渲染服务。`Actor::RemoveComponent()`、`World::RemoveActor()` 和 `World` 析构会先走 World 注销路径，由 World 调用组件的 `DestroyRenderState()` 记录 Remove 命令，再释放对象。
